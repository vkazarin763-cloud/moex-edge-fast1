## 2026-11-17
- **ПРОВЕДЕН БЭКТЕСТ ПРИНЦИПОВ ВХОДА И ВЫХОДА (2 года, 10 акций):**
  - Текущая логика (TP 5%, SL 3%) УБЫТОЧНА: -309% за 2 года.
  - Лучшая логика: Вход по пробою Donchian55 + Частичная фиксация (50% на +3%, остаток по трейлингу 2 ATR). Общая доходность: +629%, Винрейт: 48%.
  - Фильтр по ATR для входа (Multi) не улучшает результат, только сокращает число сделок. Оставляем Single.
  - **Решение:** После сбора текущей статистики перевести `ai_agent.py` на логику `PARTIAL` (частичная фиксация + ATR-трейлинг).
## 2026-11-17 (Вечер)
- **ПРОВЕДЕН ГЕНЕРАЛЬНЫЙ БЭКТЕСТ (Grid Search):**
  - Найдена идеальная связка за 2 года: Вход по пробою Donchian55 с фильтром EMA200 (TrendFilter) + Частичная фиксация 50% на +5%, остаток по трейлингу 2.0 ATR. Итог: +648% за 2 года, Винрейт 42%, средняя сделка +0.72%.
  - Текущая логика бота (Fixed 5%) показала худший результат: -309%.
  - Быстрая фиксация (на +1.5% или +3%) режет прибыль.
  - **Решение:** После окончания сбора текущей статистики полностью перевести `ai_agent.py` на связку `TrendFilter` + `Partial_5.0`.
## 2026-11-17 (Ночь)
- **ПРОВЕДЕН OUT-OF-SAMPLE ТЕСТ (2022-2023):**
  - Связка `TrendFilter Partial_5.0` (лидер 2024-2026) показала МИНУС (-21%). Подтверждена переподгонка.
  - Связка `Single Trail_2.0` (Donchian55 + ATR-трейлинг) показала ПЛЮС (+142%) в 2022-2023 и (+320%) в 2024-2026.
  - **Решение:** Для версии 2.0 использовать ТОЛЬКО `Single Trail_2.0`. Никаких фильтров EMA200 и фиксированных тейков.

## 2026-11-17 (Finam Executor — аудит и исправления)
- Принято: исправлять `finam_executor.py` как боевой компонент, не менять торговую стратегию и не запускать реальные заявки ради тестирования.
- Безопасность: `DRY_RUN` по умолчанию остаётся включённым; секреты не выводятся и не коммитятся; AI Agent/AI Trainer и их месячный виртуальный тест не затрагиваются.
- Подтверждено по логу GitHub Actions run `44123677613` (17.11.2026): конкретный запуск выполнялся с `FINAM_DRY_RUN=true`; RTKM не отправлялся, SL/TP не выставлялись; T был пропущен как уже открытая позиция. Это не объясняет происхождение ранее замеченной реальной сделки.
- В PR `#1` выявлен дефект: статусы Finam вида `ORDER_STATUS_FILLED` сравнивались с `FILLED` без нормализации; из-за этого уже завершённая заявка могла ошибочно ожидать тайм-аут и запускать отмену остатка.
- Исправлена нормализация статусов и расширен набор терминальных состояний; тест обновлён так, чтобы проверять отсутствие лишней отмены при частичном → полном исполнении.
- Исправлен тест сетевого тайм-аута: сверка client_order_id теперь изолирована mock-ответом и не обращается к реальному API.
- Сверены форматы trades и SL/TP с официальной REST-документацией Finam: `/v1/accounts/{account_id}/trades`, поля `price.value`, `size.value`, `order_id`; account_id передаётся в URL SL/TP endpoint.
- Статус: изменения находятся в отдельной ветке и PR; до успешного CI и проверки оставшихся сценариев не включать в `main` и не использовать для реальных заявок.
