# Changelog MOEX EDGE

## 2026-11-16
- **ИСПРАВЛЕН КРИТИЧЕСКИЙ БАГ в `ai_agent.py`:**
  - Устранен баг «путешествия во времени» (стопы проверялись на свечах, которые были ДО времени входа).
  - Устранен баг дублирования позиций (агент открывал по 3-4 сделки на один тикер после срабатывания стопа).
  - Время входа теперь фиксируется по часовой свече, а не по дневной (00:00).
  - Добавлен запрет на повторный вход в тикер в течение одного дня.
- Настроен внешний планировщик `cron-job.org` (HTTP POST, API GitHub, workflow_dispatch).
- Подтверждена работа Telegram-уведомлений (приходят отчеты о закрытии сделок).
- Добавлены файлы памяти проекта.

## 2026-11-15
- Аудит репозитория. Изменений кода нет.

## 2026-11-17 — Finam Executor safety patch (PR #1)
- В отдельной ветке подготовлены защита от повторной отправки при неоднозначном POST, сверка исполнения по `order_id`, расчёт VWAP и выставление SL/TP только на подтверждённое исполненное количество.
- Исправлена ошибка нормализации статусов Finam: `ORDER_STATUS_*` теперь сравниваются по нормализованному enum; терминальные статусы включают исполнение, отмену, отказ, истечение, `DONE_FOR_DAY` и `REPLACED`.
- Обновлены unit-тесты: частичное исполнение не вызывает преждевременную отмену после перехода в FILLED; тайм-аут POST тестируется без сетевого обращения к Finam.
- Боевой `main` не изменён. `DRY_RUN` не переключался. Реальные заявки не отправлялись. CI для последнего коммита ожидает проверки.

- Уточнена сверка неоднозначного POST: поиск `client_order_id` учитывает как корневое поле, так и `order.client_order_id` из структуры ответа Finam; добавлен тест.


## 2026-11-17 — Telegram secrets для Finam Executor (PR #1)
- В `.github/workflows/moex-edge-fast.yml` и `.github/workflows/finam-executor.yml` добавлена передача `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` из GitHub Actions Secrets в окружение `finam_executor.py`.
- Изменения сохранены в ветке PR #1; main не изменён. Значения секретов не раскрывались.
- Важно: при `FINAM_DRY_RUN=true` исполнитель не отправляет реальные заявки и не отправляет сообщения о выполненных сделках. Переключение DRY_RUN не производилось.
