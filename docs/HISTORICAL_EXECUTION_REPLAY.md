# Historical execution replay (development only)

The historical replay workflow now produces two separate reports:

1. `moex_edge_historical_simulation.json` — fixed-horizon descriptive outcomes.
2. `moex_edge_historical_execution.json` — trades generated by the existing `research_agent.core.generate_signals` and `research_agent.core.backtest` implementation.

## Frozen execution assumptions

The execution replay uses the existing default `BacktestConfig`, which is frozen for this cohort:

- Signal on a completed D1 close; entry at the next available D1 open.
- Stop: 3%.
- Target: 6%.
- Maximum holding period: 120 subsequent D1 bars.
- Commission: 0.1% per side.
- Slippage: 0.05% per side.
- Same-bar ambiguity: stop checked before target.
- Stop gaps fill at the bar open; target gaps fill at the target.
- Fee and slippage are charged on both entry and exit.

The default configuration is imported directly from `research_agent.core`; the execution module does not duplicate or tune the simulator.

## Scope and interpretation

- Cutoff is strict: candles dated 2026-11-20 or later are excluded.
- The frozen cohort remains `v1-frozen-2026-11-19`.
- T is excluded because its known 10:1 conversion falls inside the sample and prices are not automatically adjusted.
- Only native MOEX ISS TQBR D1 history is accepted.
- Signals are generated from the frozen five-strategy candidate set.
- Trades are non-overlapping within each symbol/strategy stream. Different strategies and different symbols are simulated independently and may overlap.
- Open terminal trades are counted but excluded from closed-trade performance statistics.
- Results are grouped by direction, strategy, strategy/direction, exit reason and symbol.
- `trade_records` contains one auditable row per simulated trade, including open terminal records. Each row is explicitly tagged `data_origin: HISTORICAL`; only rows with `status: CLOSED` and a non-null `net_return` belong in closed-trade statistics.
- Historical trade IDs are deterministic and namespaced separately from prospective signal/outcome records.

The aggregate sum of trade returns is explicitly **not** a portfolio return. This report has no portfolio capital, position sizing, allocation, leverage or short-sale collateral model. It is not a live signal, a profitability claim, a prospective holdout result or production approval.

Historical H1 confirmation is not reconstructed because the collector's H1 lookback is only 30 calendar days. This report does not write to the append-only prospective signal ledger.

## Individual trade records

The execution JSON includes the full `trade_records` array in addition to aggregate summaries. Each row preserves symbol, strategy, direction, signal/entry/exit timestamps, fill prices, net return, status and exit reason. These are simulated historical records, not broker fills or live executions. Open terminal rows are retained for audit but must not be counted as closed trades.

## Workflow

The read-only historical replay workflow runs only after a successful main-branch push-origin multi-timeframe collection. It downloads that exact run's candle artifact, independently validates it, then creates both historical reports. It has no broker secrets, account access, order endpoints or live-trading path.

Artifact name: `moex-edge-historical-simulation-<source-run-id>`.

## Regression tests

`tests/test_research_historical_execution.py` checks that the replay uses the frozen core execution behavior, excludes T and post-cutoff candles, preserves the frozen execution configuration, and applies stop-first handling when both stop and target are touched in the same bar.
